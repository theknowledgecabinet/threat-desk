Critical Danfoss controller flaw could allow unauthenticated remote code execution

CISA has rated a stack-based buffer overflow in Danfoss AK-SM 8xxA controllers as critical, noting that the vulnerability could permit remote code execution without authentication.

CVE-2026-129713

CISA issued advisory ICSA-26-328-03 on 24 November 2026, identifying CVE-2026-129713 in Danfoss AK-SM 8xxA refrigeration controllers running version 5.4.0 or earlier. The agency assigned a CVSS 3.1 score of 9.8, while the National Vulnerability Database lists a CVSS 4.0 base score of 9.3. The flaw is a stack-based buffer overflow in an unauthenticated CGI handler that processes HTTP/S POST requests, potentially leading to memory corruption and arbitrary code execution with web server privileges.

CISA stated it had received no reports of known public exploitation at the time of publication, though the advisory warns that code execution is possible. The vulnerability was reported by Carlo Meijer of Midnight Blue. Because the affected component does not require a login, strong passwords alone do not mitigate the risk, and a web server restart could interrupt access to the management interface even if cooling equipment continues to run.

Danfoss said in security advisory DSA-2026-12-01 that it plans to address the flaw in software version 5.5.x and intends to remove the option to disable Strict Mode in a future release. Until the fix is available, the company recommends enabling Strict Mode and using strong, unique passwords for user and administrator accounts.

Affected

Danfoss AK-SM 8xxA refrigeration controllers running version 5.4.0 or earlier

Actions

  • Enable Strict Mode on affected controllers to apply stronger security settings.
  • Restrict access to the web interface by keeping controllers behind firewalls and separating refrigeration control networks from business networks.
  • Use a secure VPN or protected network for any required remote technician access.
  • Check Danfoss software download pages for release notes confirming when the fix in version 5.5.x is available.
