Bitcoin Core wallet rebroadcast flaw links addresses to IP

A privacy flaw in Bitcoin Core allows observers to link public wallet addresses to node IP addresses for under 35 cents.

Bitcoin Core contributor Abubakar Sadiq Ismail reported on 25 November that a privacy flaw in the wallet’s rebroadcast mechanism allows an observer to identify the IP address of a node tracking a specific Bitcoin address. Ismail’s tests on a private regtest network identified the correct node in 30 out of 30 attempts, with an estimated cost of between 18 and 34 cents per attempt, depending on address type and Bitcoin price.

The vulnerability stems from the wallet’s automatic rebroadcast of both outgoing and incoming unconfirmed payments. This behaviour reveals that a node is tracking a receiving address, even if the operator did not initiate the transaction. The flaw affects watch-only wallets and third-party applications that load addresses into a Bitcoin Core wallet, such as Sparrow in Bitcoin Core mode and Specter Desktop. It does not allow for the theft of funds or recovery of private keys, but it connects public payment records to network activity.

Ismail noted that using Tor alongside public internet peers does not shield the public IP from this leak, though a Tor-only setup avoids exposing the IP through rebroadcast. The Bitcoin Core developer discussion points to making automatic rebroadcast of incoming payments opt-in as a longer-term fix, while cautioning that narrower changes may not close all exposure paths.

Affected

Bitcoin Core (wallet component), Sparrow (Bitcoin Core mode), Specter Desktop

Actions

  • Set -walletbroadcast=0 in Bitcoin Core configuration to stop automatic transaction announcements.
  • Broadcast outgoing payments separately if disabling walletbroadcast.
  • Check if your setup loads a Bitcoin Core wallet, including watch-only instances.
  • Consider using a Tor-only setup to avoid exposing public IP via rebroadcast.
