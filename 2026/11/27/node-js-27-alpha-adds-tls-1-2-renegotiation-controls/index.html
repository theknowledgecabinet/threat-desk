Node.js 27 alpha adds TLS 1.2 renegotiation controls

The Node.js project released version 27.0.0-alpha.0.2.0 on 26 November 2026, introducing deprecation warnings for TLS 1.2 renegotiation and fixes for HTTP connection reuse flaws.

CVE-2026-105481CVE-2026-123872

The alpha release addresses CVE-2026-105481, a flaw in the HTTP client that could accept data arriving before a request was sent as the response to that request. This issue, rated CVSS 6.5, affects Node.js 22.x, 24.x, and 26.x, and is described as an incomplete fix of CVE-2026-48931. The update also stops the HTTP agent from reusing expired idle sockets and enforces maxSessionMemory limits for HTTP/2 client requests.

The release marks TLS 1.2 renegotiation as deprecated under DEP0213, though it remains enabled by default. This change follows CVE-2026-123872, a high-severity (CVSS 8.1) client certificate authentication bypass that allows clients to change the servername during renegotiation to reach unauthorised endpoints. The vulnerability affects Node.js 22.x, 24.x, and 26.x. Neither CVE is listed by CISA as known exploited.

Developers can disable renegotiation immediately by setting allowRenegotiation: false in tls.createServer() or tls.connect(). The project recommends requesting client certificates during the first handshake using requestCert rather than relying on renegotiation. For production environments, the November security advisory lists v22.23.5, v24.22.3, and v26.13.1 as the patched releases for supported branches.

Affected

Node.js 22.x, 24.x, 26.x

Actions

  • Update to patched releases v22.23.5, v24.22.3, or v26.13.1 for production systems.
  • Set allowRenegotiation: false in TLS server or client configurations to disable TLS 1.2 renegotiation.
  • Use requestCert during the initial handshake instead of relying on renegotiation for client certificates.
  • Run the Node.js 27 alpha in staging with --pending-deprecation to identify services dependent on TLS 1.2 renegotiation.
