SAP confirms incident after GitHub tokens allegedly stolen

SAP is investigating a security incident where attackers allegedly used stolen employee tokens to alter source code on GitHub, though no customer data breach has been confirmed.

SAP has confirmed an IT security incident following the detection of suspicious activity within its development infrastructure. According to reports from Der Spiegel, which cited an internal memo, the incident is being handled under the name “Project Granite.” The German software maker stated that it detected the activity and took immediate steps to secure its services, while noting that investigators have found no evidence of unauthorised access to customer business data at this stage.

Der Spiegel reported that attackers obtained authentication tokens belonging to SAP employees, enabling them to copy and alter source code stored on GitHub. The publication cited sources suggesting the attack may have involved AI agents, a detail SAP has not confirmed. It remains unclear whether the compromised code was proprietary or part of public repositories, and whether any altered code reached software delivered to customers.

In response to the incident, Handelsblatt reported that SAP has reportedly replaced signing keys, limited access to GitHub, and suspended automated development operations. These emergency measures have reportedly affected numerous teams. SAP has not publicly disclosed which specific repositories were reviewed or whether users need to take action, leaving the scope of the compromise undefined.

Actions

  • Review GitHub audit logs to trace actions back to potentially compromised tokens.
  • Revoke credentials by user and token type to limit access.
  • Verify that automated build workflows have not ingested altered code.
  • Monitor for unauthorised changes in source code repositories.
