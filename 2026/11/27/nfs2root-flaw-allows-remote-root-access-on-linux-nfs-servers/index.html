NFS2ROOT flaw allows remote root access on Linux NFS servers

A critical heap overflow in the Linux kernel's NFS server, present since 2014, enables unauthenticated remote root compromise if port 2049 is exposed.

CVE-2026-99362

OpenSec Intelligence has disclosed CVE-2026-99362, a critical vulnerability in the Linux kernel's Network File System (NFS) server component, nfsd. The flaw, dubbed NFS2ROOT, stems from a heap buffer overflow that occurs when the server processes SEQUENCE replies in NFSv4.1 or NFSv4.2 sessions. An attacker with network access to TCP port 2049 can exploit this to corrupt kernel memory, bypass KASLR, and execute arbitrary commands with root privileges without requiring local access or user interaction.

The vulnerability affects Linux kernel versions dating back to 3.16, released in March 2014. Jérémy Jean of France’s national cybersecurity agency, ANSSI, submitted an upstream fix in August 2026, which OpenSec independently verified with a working exploit. While OpenSec has kept the exploit private, the company demonstrated that remote root access is possible in tested setups. There are currently no reports of in-the-wild exploitation, and CISA has not listed the vulnerability in its Known Exploited Vulnerabilities Catalog.

To mitigate the risk, administrators should immediately apply kernel updates from their distribution vendors. Fixed versions include Linux 5.10.275, 5.15.226, 6.1.193, 6.6.163, 6.12.117, 6.18.61, 7.3.2, and 7.4-rc1. For systems that cannot be patched immediately, restricting access to TCP port 2049 to trusted clients or disabling NFSv4.1 and NFSv4.2 where possible are recommended temporary measures.

Affected

Linux kernel versions prior to 5.10.275, 5.15.226, 6.1.193, 6.6.163, 6.12.117, 6.18.61, 7.3.2, and 7.4-rc1 with NFSv4.1 or NFSv4.2 enabled and TCP port 2049 reachable.

Actions

  • Apply the latest kernel security updates from your Linux distribution vendor and reboot the system.
  • Restrict access to TCP port 2049 to trusted clients or networks if patching is delayed.
  • Disable NFSv4.1 and NFSv4.2 if workloads allow, after checking client requirements.
  • Monitor for kernel warnings involving nfsd4_check_resp_size and unexpected shells started by kernel workers.
