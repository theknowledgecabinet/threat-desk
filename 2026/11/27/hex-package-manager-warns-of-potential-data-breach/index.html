Hex package manager warns of potential data breach

Attackers exploited a critical deserialization flaw in hex.pm to execute commands, prompting Hex to rotate credentials and warn that potential access to user data cannot be ruled out.

CVE-2026-129514CVE-2026-124283CVE-2026-133555CVE-2026-130411

Hex, the package manager for Elixir and Erlang, confirmed a cyberattack on 23 November in which attackers exploited an unauthenticated deserialization of untrusted data bug (CVE-2026-129514) to achieve remote code execution. The vulnerability, which carries a CVSS score of 10, allowed the execution of OS commands via a crafted Erlang external term format request body.

According to Hex, the attacker sent 69 malicious requests between 18:16 and 18:29 UTC, affecting six web servers. The underlying security defect was addressed within 20 minutes, and Hex replaced all hex.pm servers with patched versions that reject the payload. A firewall rule fully blocked the attacker’s traffic at 18:33 UTC. Hex stated it found no evidence of unauthorized package modifications or database changes, but noted that database and private documentation reads are not logged, hindering visibility into potential data exposure.

Because the attacker’s commands could read server credentials, Hex replaced storage, CDN, email, and database credentials, as well as the keys that sign sessions and access tokens. This action logged all users out of hex.pm and Hex clients. Hex also identified that the Ash Framework was impacted by the same class of vulnerability, which was patched on 24 November as CVE-2026-124283. Related defects were patched in the db_connection (CVE-2026-133555) and flop (CVE-2026-130411) libraries.

Affected

hex.pm, Ash Framework, db_connection, flop

Actions

  • Change hex.pm passwords and reset two-factor authentication.
  • Avoid fetching packages from third-party mirrors; rely only on repo.hex.pm.
  • Be cautious of phishing emails claiming to be from Hex, as email addresses may have been exposed.
