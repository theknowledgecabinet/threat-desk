Cisco UCS UEFI Shell flaw allows Secure Boot bypass

Cisco has released fixes for a high-severity vulnerability in UCS servers and appliances that permits attackers to bypass UEFI Secure Boot validation.

CVE-2026-20293

Cisco has published an advisory for CVE-2026-20293, a vulnerability in the Unified Extensible Firmware Interface (UEFI) Shell implementation of Cisco UCS Servers and UCS-based appliances. The flaw, rated with a CVSS base score of 7.1, is caused by the availability of memory write commands in the UEFI Shell while UEFI Secure Boot is enabled.

According to Cisco, an authenticated attacker with user or admin credentials, or an unauthenticated attacker with physical access, could exploit this by selecting the UEFI Shell boot option and using shell commands to modify UEFI memory variables. A successful exploit allows the attacker to manipulate the preboot environment, overwrite UEFI Secure Boot-related memory values, and execute unauthorized software.

Cisco has released software updates that address the vulnerability by removing memory modification commands from the shell when Secure Boot is enabled. The vendor states there are no workarounds available and advises customers to upgrade to the fixed software releases listed in the advisory.

Affected

5000 Series ENCS, UCS B-Series Blade Servers, UCS C-Series Rack Servers, UCS C845A M8, UCS C885A M8, UCS C880A M8, UCS E-Series M3/M6, UCS S-Series Storage Servers, UCS X-Series Modular System, Unified Edge, and specific UCS-based appliances including APIC Servers, HyperFlex Nodes, and Secure Firewall Management Center Appliances.

Actions

  • Upgrade to the fixed software releases specified in the Cisco advisory for your specific hardware model.
  • Verify that UEFI Secure Boot is enabled on affected devices to ensure the fix is active.
  • Restrict physical access to servers and appliances, as physical access is required for exploitation on certain platforms.
