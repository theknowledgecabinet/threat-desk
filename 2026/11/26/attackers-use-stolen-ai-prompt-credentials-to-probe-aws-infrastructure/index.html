Attackers use stolen AI prompt credentials to probe AWS infrastructure

Security firm Dragos traced AWS API calls to credentials planted in AI prompts, revealing that attackers are harvesting secrets from AI hosting providers.

Dragos reported that between July and November 2026, it sent nearly two million prompts containing unique links and decoy AWS access keys to AI hosting providers. The firm found evidence that attackers obtained approximately 200 of these test keys, some of which were tested within hours of submission. The stolen credentials generated tens of thousands of AWS API calls, indicating active exploitation of the exposed data.

Analysis of the activity shows that after validating the keys, the attackers listed Amazon Simple Storage Service (S3) buckets and searched AWS Secrets Manager and Systems Manager Parameter Store. Dragos also recorded attempts to enable hosted models in Amazon Bedrock and create new AWS Identity and Access Management (IAM) users, actions that could provide persistent access even if the original keys are revoked. The firm noted that some affected requests were rejected before the model ran, suggesting the theft occurred at the point where the provider first received traffic.

Malwarebytes noted that attackers obtained credentials even from prompts that hosting providers rejected. Neither Malwarebytes nor Dragos identified a specific malware family behind the theft. The activity did not rely on an AWS software flaw; instead, it leveraged valid credentials presented by the attackers. Dragos emphasised that encryption protects data in transit but does not hide the text from a provider that receives and processes it.

Affected

AWS access keys, S3 buckets, AWS Secrets Manager, Systems Manager Parameter Store, Amazon Bedrock, AWS IAM

Actions

  • Deactivate any live AWS keys found in prompts promptly and replace them where required.
  • Review AWS CloudTrail for unexpected use, including unfamiliar bucket listings, secret-access attempts, or new IAM users.
  • Strip credentials from prompts before submission to AI services.
  • Restrict sensitive workloads to approved providers and verify that zero-data-retention settings are effective.
