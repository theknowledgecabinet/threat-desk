1Password breach exposes customer data via compromised GitHub account

1Password disclosed that an attacker accessed backend systems through a hijacked employee GitHub account, stealing customer names and emails, though vault contents remained secure.

1Password disclosed on 25 November 2026 that an attacker compromised an employee’s corporate GitHub account to access source code and push malicious code to backend services. The intruder downloaded administrative records for a subset of customers, including names, sign-in email addresses, account identifiers, and creation dates. The company stated that customer vault contents, password keys, and account recovery keys were not accessed, and its applications continued to operate normally.

The attacker also copied source code from private repositories and accessed the company’s continuous integration and delivery (CI/CD) system, which holds infrastructure credentials. 1Password said the copied code contained no user secrets. The breach also exposed tokens from certain emailed invitations and recovery links; however, the company noted these tokens could not grant access by themselves and required a single sign-on login or a separate code sent to the user’s registered email address.

1Password disabled the affected GitHub account, revoked stolen tokens, and rotated potentially exposed internal credentials. It tightened GitHub and deployment controls and engaged independent cybersecurity experts to validate the cleanup. As a precaution, the company changed invitation and recovery codes from six digits to ten alphanumeric characters. It found no evidence that exposed setup tokens were used to take over accounts.

Affected

1Password backend systems, CI/CD system, employee corporate GitHub account

Actions

  • Monitor for phishing attempts using stolen customer names and email addresses.
  • Verify the authenticity of any unexpected 1Password invitation or recovery requests by accessing the official app or website directly.
  • Review GitHub account security controls and CI/CD credential management to prevent similar supply chain compromises.
