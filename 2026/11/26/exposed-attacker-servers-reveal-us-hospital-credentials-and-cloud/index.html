Exposed attacker servers reveal US hospital credentials and cloud listing

Analysts at Hunt.io identified exposed web directories containing US hospital credential records, a manufacturer's Azure storage listing, and law firm target maps, highlighting the risks of exposed attacker infrastructure.

Hunt.io analysts published findings on 25 November 2026 regarding three exposed web directories that revealed an intrusion crew's operations. The recovered files included 8,460 unique email addresses and 3,570 authentication records linked to a US hospital system, though researchers could not establish how the records were obtained or if they remained valid. The investigation also uncovered a valid Azure shared access signature (SAS) token used to list 155,568 objects in a manufacturer's cloud storage, exposing data organisation without evidence of file downloads.

In the legal sector, the crew maintained a target list of 563 entries and scanned over 60 named law firms for live VPNs and Citrix gateways. At Simpson Thacher & Bartlett, logs showed the crew tested approximately 100 staff email and password pairs against two Citrix gateways, but the credentials were rejected and no VPN session was recorded. Hunt.io stated that the evidence does not establish a breach of any law firm or federal agency, nor a ransomware link.

The investigation identified malicious software including a Java database driver posing as a legitimate component, an Apollo-derived Windows payload, and a Poseidon-derived Linux implant associated with the Mythic command-and-control framework. Hunt.io notified the US Cybersecurity and Infrastructure Security Agency (CISA) before publication to coordinate with affected organisations.

Affected

Azure storage (SAS tokens), Citrix gateways, Java applications

Actions

  • Review Azure storage logs for unusual listing or read activity and revoke or rotate suspected exposed SAS tokens.
  • Check VPN authentication logs for failed attempts followed by unexpected sessions.
  • Audit Java application inventories for unexpected database driver archives.
  • Treat infrastructure matches as leads to verify, not proof of compromise, as IP addresses can change hands.
