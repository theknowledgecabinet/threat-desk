Rackspace Spot breach exposed customer Kubernetes secrets

Attackers used leaked credentials to access the Rackspace Spot cloud platform, allowing them to read sensitive Kubernetes Secrets and deploy unauthorized workloads in customer clusters.

Rackspace disclosed that an unauthorised party accessed parts of its Rackspace Spot cloud platform on 17 November 2026, between approximately 00:20 and 22:00 UTC. The company stated that the intrusion was enabled by leaked credentials, which allowed the attackers to act as legitimate users within some customer organisations.

According to the notification obtained by BleepingComputer, the attackers were able to create pods in Kubernetes clusters, read Kubernetes Secrets, and list nodes and volumes. Rackspace warned that the attackers could have read any Secret stored in an affected user's clusters, as well as any Spot API tokens or refresh tokens held by that user.

The breach caused an extended outage of the Rackspace Spot administration console, temporarily preventing customers from managing their clusters and rotating potentially compromised credentials. Rackspace announced that service had been fully restored on 21 November 2026.

Affected

Rackspace Spot cloud platform

Actions

  • Reissue Spot API tokens and replace refresh tokens used in automation tools.
  • Download fresh Kubernetes configuration files and rotate credentials stored in cluster Secrets.
  • Analyse logs for databases, container registries, Git repositories, and cloud storage dating back to 17 November to identify possible abuse.
