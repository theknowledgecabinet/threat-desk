Microsoft confirms NTLM auth failures after November updates

November security updates for CVE-2026-118737 are causing authentication failures in third-party apps and devices that do not correctly implement NTLM message signing.

CVE-2026-118737

Microsoft has confirmed that customers may experience authentication issues following the installation of November security updates. These updates address CVE-2026-118737, a high-severity remote code execution vulnerability in the Windows Remote Procedure Call Runtime. The flaw stems from a timing-dependent authentication weakness that allows unauthenticated attackers to execute code remotely without user interaction on unpatched systems.

The November updates represent the first phase of NTLM message-signing improvements, designed to reduce exposure to relay attacks by ensuring authenticated NTLM sessions establish a cryptographic session key. However, Microsoft stated in an updated support document that these improvements may cause authentication failures on patched devices, particularly affecting third-party apps, authentication proxy servers, single sign-on solutions, and application packaging tools that use NTLM.

Microsoft identified that affected devices often set the NTLMSSP_NEGOTIATE_TARGET_INFO flag in their CHALLENGE_MESSAGE but provide an empty or incomplete TargetInfo field. As a temporary workaround, the company advised setting the ClientAllowUnsignedNtlm registry value to 1 under HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\Lsa\MSV1_0. Microsoft noted this is a short-term solution and recommended updating affected products or using Kerberos authentication as the long-term resolution.

Affected

Windows systems with November 2026 security updates; third-party apps and devices using NTLM authentication

Actions

  • Set the ClientAllowUnsignedNtlm registry value to 1 on affected systems as a temporary workaround.
  • Check if affected devices or applications support Kerberos authentication.
  • Contact vendors for updates compatible with the new NTLM signing requirements.
  • Monitor event logs for 'Not Found' values in Target Machine fields to identify affected devices.
