GnuPG releases fix for critical GPGME memory corruption flaw

A malicious OpenPGP key can trigger a double-free condition in GPGME, potentially allowing remote attackers to execute arbitrary code or crash applications.

CVE-2026-129975

The GnuPG project has warned that a critical vulnerability in GPGME, the standard library used by programs to interface with GnuPG, could expose application data. The flaw, tracked as CVE-2026-129975, is triggered by a malicious OpenPGP key containing an unusually long user ID.

According to the National Vulnerability Database, the bug arises when processing crafted input, where an early return following memory reallocation leaves internal buffer pointers referencing previously freed memory. This results in a double-free condition during cleanup, which a remote attacker could exploit to corrupt process memory, leading to arbitrary code execution or a denial-of-service crash.

The GnuPG project stated that fixed versions have been released. The vulnerability affects all software that uses GPGME prior to version 2.3.0. CISA has not listed this vulnerability in its Known Exploited Vulnerabilities Catalog.

Affected

GPGME before version 2.3.0

Actions

  • Upgrade GPGME to version 2.3.0 or later.
  • Audit applications that depend on GPGME to ensure they are updated.
  • Monitor for unusual process behaviour or crashes in applications handling OpenPGP keys.
