Single-bit .NET change bypasses Windows code integrity

A researcher demonstrated how a minor file alteration allows local attackers to execute untrusted code, bypassing Windows protections and VirtualBox hardening.

CVE-2026-87268

James Forshaw, a Google Project Zero researcher, published a write-up detailing how a quirk in the .NET Framework's file loading process allows a local attacker to run untrusted code. This behaviour bypasses two separate Windows code integrity protections designed to block such execution.

The same loading mechanism also circumvents process hardening in Oracle VirtualBox on Windows hosts. This specific bypass is tracked as CVE-2026-87268, affecting the Core component of Oracle VM VirtualBox version 7.2.16. The vulnerability is rated with a CVSS 3.1 base score of 7.8, indicating high severity for low-privileged local attackers.

According to the National Vulnerability Database, the vulnerability is easily exploitable and can result in the takeover of the VirtualBox instance. It applies exclusively to Windows hosts. CISA has not listed this vulnerability in its Known Exploited Vulnerabilities Catalog.

Affected

Oracle VM VirtualBox 7.2.16 (Windows host only)

Actions

  • Monitor for official patches from Oracle for CVE-2026-87268
  • Restrict local user privileges on systems running VirtualBox
  • Review .NET file loading configurations for potential integrity bypasses
